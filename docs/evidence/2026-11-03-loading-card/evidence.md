# 加载卡片保留到场景画出（2026-11-03，本机限定静音验证）

## 问题

用户反馈：刷新后先是一片绿色，过一会儿才出现场景（浣熊在码头）。

## 原因

- 整个 3D 场景挂在同一个 `Suspense` 下面（`ForestWorld.tsx` 的 `Scene`）。场景里任何一个模型还在加载，整块场景都不绘制，画布上只剩底色（绿色）。
- 加载卡片（`LoadingScreen.tsx`）只看 drei 的下载进度：第一批资源到 100% 后停 0.7 秒就消失，但后面几批资源、浣熊模型和着色器编译还在进行。
- “出现在码头”是另一个问题，见 PROGRESS：群岛旅行有“刷新回到最后停靠的泊位”的规则。

## 修改

- `uiStore` 新增 `worldDrawn` 和 `worldFailed` 两个标记。
- 浣熊组件的每帧回调只在场景挂载后才运行：确认浣熊就绪并连续画满 3 帧后，置 `worldDrawn`。
- 世界错误边界捕获到错误时置 `worldFailed`，让卡片让开，免得把错误提示挡在下面。
- 加载卡片的消失条件改为：下载进度结束，并且已经画出（或已出错）。
- 下载已满、场景还在准备时，卡片文字显示“正在准备…”，不再一直停在“100%”。

## 验证

`scripts/check_loading_card.mjs`：静音无头 Edge，1440×900，禁用缓存冷启动，每 50 ms 轮询一次。在卡片消失的那一刻记录状态并立即截图。

| 版本 | 卡片消失时 | 截图 |
|---|---|---|
| 修改前（开发服，临时恢复旧版 `LoadingScreen.tsx`） | 16.1 s，浣熊未就绪 | [全绿画布](before/run-0-card-gone.png) |
| 修改后（开发服，3 次） | 38.3 / 32.3 / 32.7 s，浣熊均已就绪 | [场景完整](after/run-0-card-gone.png) |
| 修改后（正式构建 `vite preview`，3 次） | 27.2 / 19.0 / 18.6 s | [场景完整](production/run-1-card-gone.png) |

- 正式构建没有开发遥测，只能以截图为证。
- 卡片消失的时刻变晚了，但能开始玩的时刻没有变：原来那段全绿的时间现在显示为加载卡片。
- 上面的时间都是本机禁用缓存的冷启动，不代表线上加载速度。
- JS 异常和 console.error 均为 0；oxlint 0；59 文件 278/278 单测；build 通过。
